Call another runner to share the current run, or start a child workflow
when it needs an independent lifetime.

## Calling a runner directly

A runner is an ordinary function, so another runner can call it. Its steps then
run **in the current run**, as if they were written inline.

```go
func PublishReport(ctx context.Context, input workflows.PublishReport) (workflows.PublishReportResult, error) {
	report, err := GenerateReport(ctx, workflows.GenerateReport{Topic: input.Topic})
	if err != nil {
		return workflows.PublishReportResult{}, err
	}

	location, err := workflow.Step(ctx, storeReport, report.Summary)
	if err != nil {
		return workflows.PublishReportResult{}, err
	}

	return workflows.PublishReportResult{Report: report, Location: location}, nil
}
```

Use a direct call when the work should share the current run and event log.

## Starting a child run

`workflow.Start` in workflow context starts a **child run**. The child is
started in an [inline step](/docs/inline-steps), so replay returns the
same run. Its ID is derived from that recorded step, so a retried attempt does
not start a second child. It is pinned to the deployment executing the parent, and
it carries two attributes:

| Attribute | Value |
| --- | --- |
| `$parentRunId` (`worlds.ParentRunIDAttribute`) | the run that started it |
| `$rootRunId` (`worlds.RootRunIDAttribute`) | the run at the root of the lineage |

A child run is independent: it has its own event log, can run on other
workers, and can outlive its parent.

### Waiting for a child

`Run.Value` waits for the child to finish and returns its output, or its error
as a [`*workflow.Error`](/docs/errors) when it failed:

```go
func Parent(ctx context.Context, input workflows.Parent) (workflows.ParentResult, error) {
	child, err := workflow.Start(ctx, workflows.Child{Item: input.Item})
	if err != nil {
		return workflows.ParentResult{}, err
	}

	result, err := child.Value(ctx)
	if err != nil {
		return workflows.ParentResult{}, err
	}
	return workflows.ParentResult{Value: result.Value}, nil
}
```

The parent does not poll. The child records the parent's ID in its
`executionContext`, as `completionParentRunId`, and once its `run_completed`,
`run_failed`, or `run_cancelled` is recorded, the runtime, or the
`Run.Cancel` call, resumes the parent's **child-run completion hook** with
the child's ID and status. The hook is a system hook whose token is
`wkf_child_run_completion:` followed by the parent's run ID. While it waits,
the parent:

1. registers the hook, on its first wait, and keeps it open for the rest of
   the run,
2. reads which of the children it waits for have already finished, in one
   inline step, `readFinishedRuns`,
3. suspends until a child resumes the hook, holding no worker, and
4. reads the finished child's output in an inline step, `waitForRun`.

While it waits, a timer reads the children again after 5 minutes, doubling up
to 6 hours, in case a resume was lost. A `Run` from `workflow.Get` is not a
child of the run, and `Value` waits for it in an inline step instead.

`Run.ReturnValue` returns the wait as a promise, which starts when it is
first awaited, so children awaited together are read in one step.

### Fan-out to child runs

```go
results := make([]*workflow.Result[workflows.ChildResult], len(input.Items))
for i, item := range input.Items {
	child, err := workflow.Start(ctx, workflows.Child{Item: item})
	if err != nil {
		return Output{}, err
	}
	results[i] = child.ReturnValue(ctx)
}

if err := workflow.JoinOk(ctx, workflow.MapResults(results)...); err != nil {
	return Output{}, err
}

values := make([]string, len(results))
for i, result := range results {
	values[i] = result.Unwrap(ctx).Value
}
```

Every child resumes the parent's one completion hook.

### Signalling the parent

A child can also send its parent a value before it finishes, through a hook
the parent passes it:

```go
func Parent(ctx context.Context, input workflows.Parent) (workflows.ParentResult, error) {
	hook := workflow.CreateHook[string](ctx)
	defer hook.Dispose(ctx)

	if owner, err := hook.GetConflict(ctx); err != nil {
		return workflows.ParentResult{}, err
	} else if owner != nil {
		return workflows.ParentResult{}, &workflow.HookConflictError{}
	}

	if _, err := workflow.Start(ctx, workflows.Child{Token: hook.Token()}); err != nil {
		return workflows.ParentResult{}, err
	}

	value, err := hook.Next(ctx)
	return workflows.ParentResult{Value: value}, err
}

func Child(ctx context.Context, input workflows.Child) (workflows.ChildResult, error) {
	value, err := workflow.Step(ctx, work, input)
	if err != nil {
		return workflows.ChildResult{}, err
	}

	_, err = workflow.Step(ctx, resumeParent, completion{Token: input.Token, Value: value})
	return workflows.ChildResult{Value: value}, err
}

type completion struct {
	Token string
	Value string
}

func resumeParent(ctx context.Context, c completion) (struct{}, error) {
	return struct{}{}, workflow.ResumeHook(ctx, c.Token, c.Value)
}
```

`ResumeHook` works in step context, using the World that records the run.

### Cancelling a child

A `Run` has its own `Cancel` method. Calling it in workflow context records a durable inline step. A cancelled run stops new work and lets admitted steps finish naturally:

```go
child, err := workflow.Start(ctx, workflows.Child{Item: input.Item})
if err != nil {
	return Result{}, err
}

// ...
if err := child.Cancel(ctx); err != nil {
	return Result{}, err
}
```

A child run has an independent lifetime, even when `Start` receives a cancelled context. Check the cancellation context and call `Cancel` explicitly when the child should stop:

```go
if cancelCtx.Err() != nil {
	if err := child.Cancel(ctx); err != nil {
		return Result{}, err
	}
}
```

This check only runs when the workflow reaches it and does not watch for
future cancellation. See [Cancellation](/docs/cancellation#cancelling-a-run)
for how run and context cancellation differ.
