## Workflows

A workflow is a struct type that embeds `workflow.Struct[Out]`, where `Out` is
the workflow's output type. `Struct` has no fields, so it adds nothing to the
workflow's input.

```go
package workflows

type GenerateReport struct {
	workflow.Struct[GenerateReportResult]
	Topic string
}

type GenerateReportResult struct {
	Summary string
}
```

`Struct` gives the workflow a `Workflow(Out)` method, which is what marks
the type as a workflow. A struct can declare the method itself instead:

```go
type GenerateReport struct {
	Topic string
}

func (GenerateReport) Workflow(GenerateReportResult) {}
```

The struct's package path and type name form the **workflow name**, in the
Workflow SDK's form, such as
`workflow//example.com/app/workflows//GenerateReport`. Runs record this name to
select their runner. Steps are named the same way from their function, such as
`step//example.com/app/flows//writeDraft`. Each value of the struct supplies a
run's input. Inputs and outputs use JSON, so give them exported fields and
JSON-friendly types.

A run records its input as an argument list with the struct as its one
argument. To take several arguments instead, as a Workflow SDK caller passes
them with `start(workflow, [a, b])`, embed `workflow.Args`: the struct's
exported fields become the arguments, in the order they are declared. Missing
arguments leave their fields zero, and extra ones are ignored.

```go
type Add struct {
	workflow.Struct[int]
	workflow.Args
	A, B int
}
```

Keep workflow types in a `workflows` package and their runners in a `flows`
package inside it, `workflows/flows`. Request handlers import only
`workflows`, so they can [start runs](/docs/runs) without importing runners
or their dependencies.

## Runners

A runner is a named function, or a method whose receiver holds the runner's
dependencies, that executes a workflow, kept in `workflows/flows`. Its input and output types match the workflow declaration:

```go
package flows

func GenerateReport(ctx context.Context, input workflows.GenerateReport) (workflows.GenerateReportResult, error) {
	sources, err := workflow.Step(ctx, findSources, input.Topic)
	if err != nil {
		return workflows.GenerateReportResult{}, err
	}

	return workflows.GenerateReportResult{Summary: strings.Join(sources, ", ")}, nil
}
```

The runner's code runs in **workflow context**. It replays on every delivery,
so it must be deterministic. See [How Replay Works](/docs/replay).

Returning an error fails the run. The run's error is recorded as a
[`*workflow.Error`](/docs/errors), and any [rollbacks](/docs/rollbacks)
registered so far run first.

## Registering runners

`workflow.Use` registers a runner for its workflow and returns a
`worlds.Runner`. `worlds.Runners` collects runners into a `worlds.RunnerSet`,
which you pass to the World or worker that executes deliveries.

```go
runners := worlds.Runners(
	workflow.Use(flows.GenerateReport),
	workflow.Use(flows.PublishReport),
)
```

Only processes that execute deliveries need runners. An application that only
starts and reads runs needs the workflow types and a [Client](/docs/runs#clients).

A run that names a workflow with no registered runner fails with
`worlds.ErrWorkflowNotRegistered`.

## Suggested layout

<Files>
  <Folder name="workflows" defaultOpen>
    <File name="reports.go" />
    <Folder name="flows" defaultOpen>
      <File name="generate_report.go" />
      <File name="publish_report.go" />
    </Folder>
  </Folder>
  <Folder name="cmd" defaultOpen>
    <Folder name="app" />
    <Folder name="worker" />
  </Folder>
</Files>

`workflows` holds the workflow types and is imported by both the application and
the flows. `workflows/flows` holds runners and their steps and is imported only
by workers. `cmd/app` starts runs with a Client, and `cmd/worker` opens a World
with the runners.

## Workflow metadata

`workflow.GetWorkflowMetadata` returns information about the run that the
context belongs to, in both workflow and step context.

```go
meta := workflow.GetWorkflowMetadata(ctx)
log.Printf("workflow %s, run %s, started %s", meta.Name, meta.RunID, meta.StartedAt)
```

Outside a run it returns the zero `WorkflowMetadata`.
