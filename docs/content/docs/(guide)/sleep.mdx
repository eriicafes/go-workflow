A suspended run holds no process, goroutine, or connection. Timers are stored
in the World as deliveries due at a future time, so sleeping for days or weeks
is fine.

## Sleep

`workflow.Sleep` suspends the run for a duration. Use it instead of
`time.Sleep`.

```go
if err := workflow.Sleep(ctx, 24*time.Hour); err != nil {
	return Result{}, err
}
```

`Sleep` is `Timer` followed by `Value`.

## Timers

Use `workflow.Timer` when the runner needs to do other work during a wait.
For example, race an approval hook against a reminder timer:

```go
approved := workflow.CreateHook[struct{}](ctx, workflow.HookOption{Token: "approve:" + input.OrderID})
defer approved.Dispose(ctx)

reminder := workflow.Timer(ctx, 48*time.Hour)

winner, err := workflow.Select(ctx, approved, reminder)
if err != nil {
	return Output{}, err
}

if winner == reminder {
	if _, err := workflow.Step(ctx, sendReminder, input.OrderID); err != nil {
		return Output{}, err
	}
}
```

A timer returns a result you can wait on or use in
[selection](/docs/concurrency#racing-operations). It settles when replay
reaches its declaration after the due time. Waiting code sees the result in
recorded event order.

A [cancellation context](/docs/cancellation) can end the wait early.

## Timeouts and deadlines

To stop work after a duration or at an absolute deadline, pass it a context
created with `workflow.WithTimeout` or `workflow.WithDeadline`. See
[Cancellation](/docs/cancellation#timeouts-and-deadlines) for examples and
expiry behavior.

## Reading the time

Use `workflow.Now` instead of `time.Now` in a runner. In workflow context it
returns the **replay clock**, which records nothing:

- it starts at the run's creation time, read from the run ID;
- it moves forward to an event's creation time when the event's outcome is
  delivered to the runner: a step's result, a timer firing, a hook's
  registration, a cancellation, and a hook payload when `Next` takes it.

Every replay delivers the same outcomes in the same order, so it reads the
same time at the same point.

```go
deadline := workflow.Now(ctx).Add(72 * time.Hour)
```

`Now` returns UTC in whole milliseconds. Outside workflow context, including
in step context, it returns `time.Now()`. `Sleep`, `Timer`, `WithTimeout`, and
a hook's `MinRetention` measure from the replay clock too.

## Waking a run early

`Run.WakeUp` settles a run's pending timers early and queues a delivery so the
run resumes. It returns the number of timers it settled. This is useful for
operators who want to skip a wait. In tests, run the World under
[synctest](/docs/testing#sleeps-and-timers) instead, which skips waits without
touching the run.

```go
run, err := workflow.Get[Result](ctx, runID)
if err != nil {
	return err
}

n, err := run.WakeUp(ctx)
```

Set `WakeOptions.CorrelationIDs` to wake only specific waits. Waking a timer
used by a [timeout or deadline](/docs/cancellation#timeouts-and-deadlines)
also triggers its cancellation.

## Delivery limits

Each World reports how far ahead its queue can schedule a delivery
(`Capabilities().MaxQueueDelay`). A timer further away is reached in hops
anchored on its deadline: the last hop is due with the timer, each earlier one
the World's limit before the next, and a hop's delivery only queues the next
one. A step retry that is further away than the limit asks for its message
again when it is delivered early.

| World | Delay limit |
| --- | --- |
| Vercel | 23 hours |
| AWS | 15 minutes, none with `Config.Scheduler` (EventBridge Scheduler) |
| Postgres | none |
| Local | none |
