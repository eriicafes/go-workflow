# Workflow SDK tests go-workflow does not port, one per line:
#
#   <upstream file>[ > <describe or test name>] -- <reason>
#
# A file skips all its tests, and a describe block all the tests in it. Every
# other test of internal/sdkdrift.WorkflowSDK.TrackedDirs is ported to a Go
# test that names it in a `// SDK: <file> > <test name>` comment.

# JavaScript and Node.js runtime concerns, which Go has no counterpart of.
packages/errors/src/ansi.test.ts -- ANSI coloring of error output; Go errors are plain strings.
packages/errors/src/build-error.test.ts -- errors of the SDK's build step; Go programs have none.
packages/errors/src/dynamic-workflows-not-enabled-error.test.ts -- dynamic workflow code; Go workflows are compiled in.
packages/errors/src/module-scope-state.test.ts -- JavaScript module-scope state across bundles.
packages/world-local/src/module-scope-state.test.ts -- JavaScript module-scope state across bundles.
packages/world-postgres/src/module-scope-state.test.ts -- JavaScript module-scope state across bundles.
packages/world/src/node-http.test.ts -- the SDK's Node.js HTTP transport; Go uses net/http.
packages/world/src/node-http-flag.test.ts -- the SDK's Node.js HTTP transport flag.
packages/world/src/env-config.test.ts -- the SDK's environment variable parsing; Go Worlds take a Config.
packages/world-local/src/instrumentObject.test.ts -- OpenTelemetry instrumentation wrappers of world-local's JavaScript objects.
